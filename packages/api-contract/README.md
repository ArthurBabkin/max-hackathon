# packages/api-contract

Контракт между мини-приложением (`apps/web`) и `fn: api` (`apps/api`).

| Файл | Что это |
| --- | --- |
| `openapi.yaml` | **Источник истины.** OpenAPI 3.1, выведен из раздела 10 ТЗ и схемы `packages/db/migrations/0001_init.sql` |
| `types.gen.ts` | Генерируется из yaml, коммитится. Руками не правится |
| `index.ts` | Короткие имена поверх сгенерированного: `OlympiadCard` вместо `components['schemas']['OlympiadCard']` |

## Как менять

Правится **только `openapi.yaml`**, дальше из `apps/web`:

```bash
npm run contract
```

Команда перегенерирует `types.gen.ts`. Коммитить оба файла вместе — иначе
сборка фронта разойдётся с контрактом.

Любое изменение, ломающее совместимость, обсуждается с обеими сторонами до
коммита: контракт читают и фронт, и бэкенд.

## Соглашения

- **snake_case на проводе.** Так устроены колонки БД, так маршалит sqlc и так
  уже написан `packages/shared/maxapi/types.go`. Трансформера камелизации нет
  ни на одной стороне. В ТЗ §10 тело `POST /tracker` записано как `{profileId}` —
  это неформальная запись в таблице, в контракте поле называется
  `olympiad_profile_id`.
- **Ошибка всегда объект:** `{"error": {"code", "message"}}` — как требует ТЗ §10.
  Скелет `apps/api/internal/api/router.go` сейчас отдаёт `error` строкой; это
  расхождение с ТЗ, и приводить надо скелет. Клиент временно принимает обе формы.
- **Даты** — RFC 3339 в UTC; «только дата» (`verified_at`, `rules_verified_at`) —
  `YYYY-MM-DD`.
- **`null` значит `null`.** `level` пуст у ВсОШ и у олимпиад вне перечня,
  `source` пуст там, где факт ещё не выверен — тогда клиент не ставит метку
  «Факт» и пишет «данные уточняются» (ТЗ F18).
- **Права считает сервер** по матрице ТЗ §3.1 и отдаёт готовые флаги в
  `session.permissions`. Клиент рисует по ним кнопки, но защитой это не считает.
- **Скоринг подбора — на сервере** (ТЗ §6.1). `GET /recommendations` возвращает
  готовый порядок и строку-причину; фронт порядок не меняет и свой скоринг
  не считает.

## Идентификаторы олимпиад

Всё, что адресует олимпиаду, использует `olympiad_profile_id`, а не
`olympiad_id`: льгота по ТЗ §6.2 — это связка «профиль + вуз + год», и
`tracker_items` в схеме БД ссылается именно на профиль.

Исключение — каталог `GET /olympiads`: там одна строка на олимпиаду, и в
`primary_profile` лежит профиль, который откроется по тапу (совпадающий с
предметами ученика либо первый).

## Проверка против живого API

Из `apps/web`:

```bash
npm run contract:check
```

Дёргает каждую ручку у запущенного API и печатает статус с ключами верхнего
уровня — так переименования видно в тот же день, когда они появились.
