# apps/landing — лендинг «Траектории»

Презентационная страница продукта на собственном домене
**https://traektoriaedu.ru/**. Это не часть мини-приложения: мини-приложение
открывается только внутри MAX, а лендинг — обычный сайт для жюри, школьников
и родителей. Все кнопки ведут в бота [@t356_hakaton_max_bot](https://max.ru/t356_hakaton_max_bot).

Страница сверстана 1:1 по макетам из [docs/landing](../../docs/landing/README.md):
[desktop-1440.html](../../docs/landing/html/desktop-1440.html) — от 1024 px,
[mobile-390.html](../../docs/landing/html/mobile-390.html) — до 767 px. Между
ними (768–1023) — планшетная раскладка: тексты десктопа, сцена hero и меню
из мобильного макета. Тема только светлая, как в макетах.

## Запуск

Сборки нет — это статика. Любой статический сервер из этой папки:

```bash
python3 -m http.server 5180 --directory apps/landing
```

## Тесты

```bash
node --test apps/landing/landing.test.mjs
```

Без зависимостей, на встроенном `node:test`. Страница сверяется с макетами:
порядок секций, все тексты, ссылки и `alt` картинок в каждой раскладке — в том же
порядке, что в `docs/landing/html` (элементы другой раскладки отбрасываются по
классам видимости). Ещё тесты ловят то, что в статике ломается тихо: файл, на
который ссылается страница, отсутствует или лежит без ссылок; якорь ведёт на
удалённую секцию; у картинки нет `alt` или размеров; кнопка ведёт не в нашего
бота; подключён скрипт или стиль с чужого домена; контраст пар токенов ниже
4.5:1 (ТЗ §12). Поведение из `main.js` (вопросы, смена экранов, меню, шапка)
проверяется на поддельном DOM. Те же тесты гоняют CI и выкладка.

## Что где лежит

| Файл | Что это |
| --- | --- |
| `index.html` | вся разметка и тексты обеих раскладок |
| `tokens/tokens.css` | токены дизайн-системы, копия `docs/landing/tokens/tokens.css` без правок |
| `styles.css` | токены, которых нет в дизайн-системе (цвета макетов), и вёрстка: десктоп, затем планшет, затем мобильный |
| `main.js` | прогрессивное улучшение: вопросы, смена экранов, меню, плашка шапки |
| `fonts/` | Onest и Unbounded (SIL OFL 1.1), вариативные, урезаны до кириллицы и латиницы |
| `assets/logo/` | логотип, иконка сайта, превью ссылки 1200×630 |
| `assets/screens/` | экраны из `docs/landing/assets/screens` в WebP, 292 и 584 px по ширине |

**Раскладки.** Где тексты мобильного и десктопного макетов различаются, в
разметке лежат оба варианта, а показывают нужный классы `m-only` (до 767),
`d-only` (от 768), `wide-only` (от 1024), `narrow-only` (до 1023). Сцена hero на
широком экране масштабируется целиком: координаты в единицах `--u` = 1/1280
ширины контейнера.

**Без JS страница работает целиком:** все ответы на вопросы открыты, меню
не нужно — навигация есть в подвале, экраны просто стоят на первом.

**Движение.** Экраны в hero и в блоке «Что умеет» раз в 3,5 с сменяются вторым.
При `prefers-reduced-motion` всё статично, прокрутка к якорю без анимации.

**Шрифты урезаны** до нужных символов, иначе они весят 380 КБ:

```bash
pyftsubset docs/landing/fonts/Onest-Variable.woff2 --output-file=apps/landing/fonts/Onest-Variable.woff2 \
  --unicodes="U+0020-007E,U+00A0-00FF,U+0131,U+0152-0153,U+02C6,U+02DA,U+02DC,U+0400-045F,U+0490-0491,U+2010-2027,U+202F,U+2030-203A,U+2044,U+20BD,U+2116,U+2122,U+2190-2193,U+2212,U+2248,U+2260,U+2264-2265" \
  --flavor=woff2 --layout-features='*' --layout-scripts='*' --glyph-names --legacy-kern \
  --notdef-outline --name-IDs='*' --name-languages='*' --no-prune-unicode-ranges --no-recalc-bounds --hinting
```

То же для `Unbounded-Variable.woff2`. Флаги сохраняют кернинг и хинтинг: без них
текст рендерится на субпиксель иначе, чем в макете.

**Экраны меняются вместе с `docs/landing/assets/screens`.** Исходники там
уже 584 px (2×), пересобрать WebP:

```bash
for f in docs/landing/assets/screens/*.png; do
  n=$(basename "$f" .png)
  cwebp -quiet -q 82 -alpha_q 100 -m 6 "$f" -o apps/landing/assets/screens/$n-584.webp
  cwebp -quiet -q 85 -alpha_q 100 -m 6 -resize 292 0 "$f" -o apps/landing/assets/screens/$n-292.webp
done
```

## Выкладка

При слиянии в `master` с изменениями в `apps/landing/` воркфлоу
[Deploy landing](../../.github/workflows/deploy-landing.yml) прогоняет тесты
и заливает папку в бакет `traektoriaedu.ru` (кроме тестов и README).
Бакет, DNS и сертификат создаёт Terraform (`infra/terraform`), пайплайн их
не трогает. У файлов нет хеша в имени, поэтому ассеты кешируются на час,
`index.html` — без кеша.
