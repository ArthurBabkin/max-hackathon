# apps/web — мини-приложение «Траектория»

Мини-приложение MAX: подбор олимпиад, карточки с льготами, трекер сроков,
семейная траектория и ИИ-помощник. Экраны C1–H4 из [docs/screens](../../docs/screens),
поведение и тексты — по [прототипу](../../docs/prototype/index.html).

Экраны A\*, B\* и I\* — это сообщения бота, они в `apps/bot`.

## Запуск

```bash
npm ci
npm run dev
```

Откроется на `http://localhost:5173` с моками — бэкенд для разработки не нужен.

> **npm 11 или новее.** В npm 10.9 есть баг arborist: `npm install` падает на
> peer-дереве Vitest 5 с «Cannot read properties of null (reading 'edgesOut')».
> `npm ci` по готовому локу работает и на npm 10, поэтому Docker-сборке это
> не мешает.

Весь стенд целиком, вместе с Go-сервисами и базой:

```bash
docker compose -f ../../infra/docker-compose.yml up --build
```

Мини-приложение будет на `http://localhost:8083`, его nginx проксирует `/api/`
в сервис `api`.

## Переключатели для разработки

Работают только в dev-режиме, в прод-бандл не попадают:

| Параметр адреса | Что делает |
| --- | --- |
| `?as=parent` | смотреть глазами родителя — проверка второго голоса из ТЗ F3 |
| `?mock=empty` | пустой подбор и каталог — экран H3 |
| `?mock=error` | запросы падают — экран H4 |
| `?dev_user=new` | на живом API — вход того, кто анкету в боте не прошёл: «Пройти анкету в чате бота» |

Пример: `http://localhost:5173/?as=parent#/tracker`.

Стек карточек лежит в адресе, так что любой экран открывается по прямой
ссылке: `#/match?sheet=oly:hse:inf,vuz:inno`.

## Как это устроено

```
src/
  main.tsx          провайдеры, баннер ошибок, старт сессии
  App.tsx           шапка, вкладки, стек листов, кнопка «Назад» MAX
  api/              клиент, запросы TanStack Query, dev-моки
  bridge/           типизированный window.WebApp и заглушка (ТЗ 11.4)
  voice/            выбор текста kid/parent
  lib/              логика без React — здесь живут тесты
  ui/               компоненты, которых нет в MAX UI, и токены
  screens/          по файлу на экран
```

Несколько решений, которые стоит знать до правок.

**Контракт API лежит в [packages/api-contract](../../packages/api-contract).**
Правится только `openapi.yaml`, типы генерируются. Копий внутри `apps/web` нет.

**Тексты — в [packages/shared/texts](../../packages/shared/texts).** Словарь
общий с ботом: обращение на «ты» и на «вы» должно совпадать во всех сообщениях
(ТЗ F3). Падежи имени ученика считает `lib/declension`: MAX отдаёт только
именительный, а родителю нужно «Цель Артёма» и «Предложить Артёму».

**«Вопросы и ответы» — статичный контент.** Разделы, порядок и первоисточники —
в `lib/faq.ts`, тексты — в общем словаре (`faq.<id>.q` / `faq.<id>.a`), чтобы
ученику и родителю отвечать своим голосом. Правила льгот сверены с законом
«Об образовании» (ст. 71) и Порядком приёма (приказ № 821); меняются они раз
в год, поэтому API под них не заведён.
**Регионы — из `packages/core/refdata/regions.json`** (алиас `@regions`), того же
справочника, по которому бот определяет регион. Цели и предметы приходят с
сервера (`GET /directions`, `GET /subjects`): они живут в базе, и профиль с
каталогом видят то же, что бот. Города в фильтре каталога вузов — из самих вузов.

**Главное действие листа — в подвале** (`footer` у `ui/Sheet.tsx`): «Добавить
в трекер» в карточке олимпиады, «Добавить в мои вузы» в карточке вуза, «Готово»
в выборе направлений. Подвал вне прокрутки, поэтому кнопка видна сразу, какой
бы длинной ни была карточка.

**Туториал новичка** (`ui/Tutorial.tsx`) — девять шагов по настоящим экранам:
главная, список олимпиад и карточка олимпиады с кнопкой «Добавить в трекер»
(родителю — «Предложить»), список вузов и карточка вуза, трекер, календарь с
кнопкой «Выгрузить в календарь», «Подбор», помощник. Между карточками шагов
пользователь сам делает одно нажатие: подсвечивается вкладка или строка с
подписью «Нажми «Каталог»», и туториал ждёт, пока её нажмут; остальное в это
время не нажимается. Цели на карточках шагов («Добавить в трекер») не
нажимаются — это настоящие действия. Открытый лист закрывается молча. В
карточке шага — путь («Каталог → Вузы»), по которому туда попасть самому;
«Назад» переходит сразу, без нажатий. Окно едет к цели, когда та встала на
место (лист выехал, экран догрузился), и перемеряет её после прокрутки и
конца анимации — кнопка в подвале листа встаёт на место без прокрутки. Карточка
сдвигается через `translate` — так переезд не дёргается.
Шаг — строка в `STEPS`: путь из нажатий (вкладка, переключатель, строка,
«Спросить»; уже сделанные пропускаются), цель подсветки и запасная цель на
случай пустого экрана. Высокая цель — список целиком — подсвечивается с
начала, карточка ложится поверх её низа; если над карточкой цели осталось бы
мало (iPhone SE, MAX со своей шапкой), цель поднимается к верху ленты. На
экранах ниже 700 px карточка компактнее. Кнопки и цели помечены атрибутом
`data-tour`, тексты — ключи `tutorial.N.*`. Сколько ждать загрузку экрана —
контекст `TutorialPace`.
Отметка «видел» — в `localStorage` (`lib/tutorial.ts`): это удобство, а не
данные, поэтому сервер о ней не знает; без хранилища туториал просто покажется
ещё раз. Показывается новичку, который открыл приложение сам или кнопкой бота
«Открыть» (`start_param=home`); переход из бота в конкретный раздел не
перебивает. `?tutorial=1` — пройти заново (ссылки в профиле и в «Вопросах и
ответах»).

**Логотипы вузов и олимпиад — в `public/logos/<id>.png|svg`**, список — `LOGOS`
в `lib/badge.ts`. Это значки с официальных сайтов и со страниц олимпиад на
olimpiada.ru: знак обрезан по краям и вписан по центру квадрата 128 px. У
олимпиады ставим её собственный знак, логотип вуза-организатора не берём;
исключение — олимпиады РГГУ, РАНХиГС, СПбГУ (у СПбГУ герб серый, у вуза —
красный), Сеченовская (знак университета), ОРМО (знак ТГУ), «Твой путь в
настоящую науку» (знак НГУ, как на сайте олимпиады), «Финатлон» (знак
Финансового университета), Инженерная и «Росатом» (знаки НИЯУ МИФИ),
Санкт-Петербургская (знак Академии талантов) и «Потомки Менделеева» (общий знак
олимпиад КФУ — тот же файл, что у его межрегиональных предметных). Где своего
знака нет ни на сайте, ни на olimpiada.ru, он нарисован в SVG по тому, что у
олимпиады есть: «Миссия выполнима» — золотой глобус с её баннера, Оборонно-
техническая — «ОТО» и радужный шестигранник с баннера, Открытая по
программированию — приглашение командной строки в цветах сайта. У ВсОШ по
каждому предмету свой знак из брендбука (vserosolimp.edsoo.ru/brendbook), для
предмета без него — общий «ВС{}Ш». Знак есть у каждой олимпиады сида — это
проверяет тест; плитка с аббревиатурой остаётся у вымышленных олимпиад
локального стенда и на случай, если файл не загрузился: кегль ужимается под
ширину плитки и число букв.

**Шрифт MAX UI переопределён в `ui/tokens.css`.** Провайдер MAX UI ставит на
свой корень системный шрифт платформы, и без переопределения `--family-base`
на `.max-root` весь интерфейс рисовался бы в Roboto или SF, а не в Onest.
Имя `--font` занято самим MAX UI, поэтому наш токен называется `--font-app`.

**Скоринг подбора на клиенте не считается.** `GET /recommendations` возвращает
готовый порядок и строку-причину (ТЗ §6.1). Вторая реализация разъехалась бы
с серверной.

**Права приходят флагами в сессии.** Сервер считает матрицу ТЗ §3.1 и
проверяет её при каждом запросе; клиент по флагам только выбирает, что
нарисовать.

**Моки живут исключительно в разработке.** Подключаются динамическим импортом
под `import.meta.env.DEV`, поэтому из прод-бандла выпадают целиком — прод
ходит только в живой API.

**Стек карточек — в адресе, а не в состоянии.** Кнопка «Назад» в MAX
системная и ходит по истории браузера. Если бы стек лежал в состоянии
компонента, первое же нажатие закрывало бы всё мини-приложение.

## Тесты

```bash
npm test
```

Покрыта логика, а не вёрстка: пороги плашек сроков, матрица прав ТЗ §3.1,
склонение имён, словарь текстов, производные величины экранов, разбор ошибок
API, поведение моков и стек карточек. Плюс три компонентных теста на то, что
пересекается: кнопка на карточке при разных ролях, стопка листов
«олимпиада → вуз → Назад» и наличие действия в пустых и ошибочных состояниях.

Playwright сознательно не берём: он проверял бы моки, а не продукт, и всё
равно не дотягивается до вебвью MAX. Сквозной сценарий из ТЗ §14 проверяется
вручную по чек-листу там же.

## Что проверить руками перед сдачей

- Оба голоса на всех пяти вкладках, включая пустые и ошибочные состояния.
- Состояния H2, H3, H4 — через `?mock=` и офлайн в DevTools.
- Тёмная тема.
- На живом телефоне в MAX: кнопка «Назад», открытие внешних ссылок,
  отправка приглашения, безопасные зоны, отсутствие баннера ошибок.
- Демо-сценарий из ТЗ §14 целиком, без тупиков.
