# MAX: API, документация, мини-приложения

Справка по платформе MAX для нашего проекта. Проверено 21 сентября 2026.

## Наш бот

```
username:  @t356_hakaton_max_bot
имя:       «Хакатон МАХ 356»
user_id:   426643746
```

Токен выдан организаторами капитану на почту и лежит в `.env` в корне репозитория (`API MAX = ...`). Файл в `.gitignore`, в репозиторий не попадает. В коде читать из окружения, в документы и коммиты не вставлять.

Проверка, что токен жив:

```bash
curl -s -H "Authorization: $MAX_TOKEN" https://platform-api2.max.ru/me
```

Отвечает JSON с `user_id`, `username`, `is_bot: true`. Работают оба хоста — `platform-api.max.ru` и `platform-api2.max.ru`; в актуальной документации указан второй.

## Bot API

- Базовый URL: `https://platform-api2.max.ru`
- Авторизация: заголовок `Authorization: <access_token>`. Токен в query-параметрах больше не поддерживается.
- Методы: GET, POST, PUT, DELETE, PATCH. Ответы — JSON плюс стандартные коды: 200, 400, 401, 404, 429 (лимит), 503.
- Лимит: около 30 запросов в секунду.

Разделы API:

- **messages** — отправка, редактирование, получение и удаление сообщений
- **chats** — групповые чаты и каналы
- **updates** — получение событий
- **upload** — загрузка медиафайлов
- **subscriptions** — webhook-подписки на события
- **comments** — комментарии к постам

Два способа получать события: long polling через `/updates` либо webhook-подписка. **Для хакатона использовать webhook.** Организаторы на вебинаре прямо сказали: long polling изначально предназначался только для разработки, не для прода, и от него отказываются.

Официальные SDK: TypeScript / JavaScript (`@maxhub/max-bot-api`) и Go, лежат на GitHub. Для Python официального нет, но есть сообществом написанные `maxapi`, `maxgram`, `aiomax`.

## Мини-приложения (Mini Apps)

Мини-приложение — обычный статический сайт (HTML, CSS, JS), который хостится на нашей стороне и открывается поверх чата.

Требования к URL:

- только https
- максимум 1024 символа
- латинские буквы, цифры, точки и дефисы, без пробелов

Подключение на фронте — один скрипт, отдельная инициализация не нужна:

```html
<script src="https://st.max.ru/js/max-web-app.js"></script>
```

Библиотека кладёт в страницу глобальный объект `window.WebApp`:

```javascript
const user = window.WebApp.initDataUnsafe.user;
console.log(user.first_name);

window.WebApp.BackButton.show();
window.WebApp.BackButton.onClick(() => { /* ... */ });
```

Что даёт Bridge: `initData` и `initDataUnsafe`, `platform`, `version`, `deviceName`; управление вьюпортом, яркостью и скриншотами; запрос номера телефона, сканирование QR, скачивание файлов; хранилище устройства и защищённое хранилище; биометрия; NFC; хаптика; кнопка «Назад» и открытие ссылок.

Важно: `initData` нужно валидировать на бэкенде — этому посвящён отдельный раздел документации, там же про `WebAppStartParam` (стартовые параметры при открытии).

Отладка: внутри мессенджера консоли нет, это отдельная боль. Разбор способов — https://habr.com/ru/articles/1039030/

## Зачем форма от организаторов

В обычном сценарии URL мини-приложения привязывается к боту в кабинете https://business.max.ru/ — раздел «Чат-бот и мини-приложение» → «Настроить». Доступ туда есть только у юрлиц, ИП и самозанятых — резидентов РФ, плюс модерация карточки бота до 48 часов.

Наш бот создан организаторами, доступа к их кабинету у команды нет. Поэтому ссылки на мини-приложения они собирают формой и прописывают URL за нас:

https://sbor-ssylok-dlya-mini-prilojeniy.testograf.ru/

Порядок такой:

1. Задеплоить фронт на https-хостинг: GitHub Pages, VK Cloud или Yandex Cloud.
2. Отправить ссылку через форму.
3. У бота появляется кнопка открытия мини-приложения.

Форму имеет смысл отправить заранее, с рабочим URL: содержимое потом можно перезаливать по тому же адресу, ссылка не меняется.

## Ограничение по публикации

С августа 2025 публикация ботов в MAX доступна только верифицированным юрлицам РФ. На хакатон это не влияет — бот уже создан и выдан организаторами.
