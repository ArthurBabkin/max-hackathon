# Парсер датасетов A и B

Собирает `vuz_napravleniya.json` (A) и `vuz_napravlenie_olimpiady.json` (B)
по `data_format_spec_4.md`: 10 вузов × 4 профильные группы, приём **2026** года.

## Запуск

```bash
pip3 install 'pdfplumber==0.11.10' pypdf lxml pyyaml requests  # 0.11.5 портит текст PDF МГУ
python3 parser/rsr_index.py     # перечень №669 -> общие справочники
python3 parser/fetch.py         # 73 документа -> snapshots/ (+ sha256)
python3 parser/extract_pdf.py   # PDF/DOCX -> extracted/*.pages.jsonl
python3 parser/build_a.py       # -> data/vuz_napravleniya.json
python3 parser/build_b.py       # -> data/vuz_napravlenie_olimpiady.json
python3 parser/validate.py      # чек-лист раздела 5 спеки; код возврата 1 при ошибке
```

Самопроверки модулей: `python3 parser/classify.py`, `python3 parser/olymp_match.py`.

## Файлы

| файл | назначение |
|---|---|
| `sources.yaml` | реестр источников: 10 вузов, 73 документа, роли `rules`/`olymp_list`/`vsosh_list`/`programs`/`kcp` |
| `fetch.py` | скачивание со снапшотами и хешами; обходит кириллические URL, Nextcloud, битый SSL Сеченова, протухающий `buildId` ИТМО |
| `extract_pdf.py` | постраничный текст и таблицы; отдельно проверяет качество извлечения (доля кириллицы, наличие цифр) |
| `rsr_index.py` | перечень №669 с rsr-olymp.ru -> `olympiad_index_669.json`, `subject_slugs.json` |
| `olymp_match.py` | название олимпиады у вуза -> номер в перечне -> `olympiad_id` |
| `classify.py` | программа вуза -> `profile_group` с пометкой `exact` / `adjacent` |
| `build_a.py`, `build_b.py` | сборка датасетов |
| `validate.py` | чек-лист спеки и эталонные льготы, сверенные с первоисточником (в CI — через `test_validate.py`) |

## Для исполнителя датасета C

Возьмите из `data/` два файла и стройте `olympiad_id` **только по ним** —
тогда join `B.olympiad_id -> C.olympiad_id` сойдётся без переписки:

- `olympiad_index_669.json` — 83 олимпиады, 303 строки «олимпиада × профиль»,
  у каждой готовый `olympiad_id`, номер по перечню и уровень;
- `subject_slugs.json` — таблица 1.3 спеки, достроенная до всех 99 профилей
  перечня (`in_spec: true` — значение зафиксировано спекой, `false` — выведено формулой).

Важно: в спеке «Высшая проба / информатика» приведена как `p669-12-informatika`,
но в действующем перечне №669 Высшая проба — **№ 8**, то есть `p669-8-informatika`.
Пример в спеке иллюстративный; номера берём из перечня.
Формула проверена на эталоне: у МФТИ номер перечня напечатан прямо в таблице,
матчер совпал с ним в 144 случаях из 144.

## Что важно знать о данных

- **Порог подтверждения ЕГЭ не константа.** Встречаются 75 / 80 / 85 / 90.
  У МФТИ два разных порога: 75 подтверждает «100 баллов», 80–85 подтверждает БВИ.
- **Три модели льгот.** Вуз либо перечисляет конкретные олимпиады, либо задаёт
  профиль («любая перечневая олимпиада этого профиля» — так устроены звёздочки
  у МГУ, приложение 3 КФУ, таблицы НГУ и строки «Все из перечня» у ИТМО),
  либо строит матрицу «олимпиада × подразделение» (МФТИ, физтех-школы).
- **Сеченов не даёт БВИ по перечневым олимпиадам вообще** — только 100 баллов.
  Дословно, приложение 5, стр. 1: «Право приема без вступительных испытаний
  по результатам олимпиад школьников Университетом не предоставляется».
- **КФУ с 2026 даёт БВИ по перечневым** (раньше только 100 баллов) —
  логика, перенесённая с правил 2025, даст неверный результат.
- **Иннополис**: льготы по ст. 71 и грантовый конкурс — разные вещи.
  В датасет попали только первые; «освобождение от 1 тура» в гранте льготой не является.
- **Ширина таблиц PDF гуляет.** Одну и ту же таблицу приложения 3 Иннополиса
  pdfplumber отдаёт в 5, 7 или 11 колонок, смотря по странице; разбор по номеру
  колонки терял стр. 8, 9, 11 и 16. Ячейки берутся вокруг ячейки уровня
  (`innopolis_rows()`). У МГУ объединённые ячейки профиля, перечня, класса и
  предмета ЕГЭ у строк-продолжений пустые — они переносятся вниз (`msu_rows()`).
- Плоские перечни («список на весь вуз») применяются к программе только если
  предмет олимпиады осмыслен для её профильной группы — иначе биология
  попадала бы на «Фундаментальную математику». Фильтр — `subject_fits()` в `build_b.py`.
  Где вуз адресует льготу точнее, фильтр не нужен: МФТИ — `mipt_link()`
  (школа и конкурсные группы), ИТМО — `itmo_merged_rows()` (блоки
  направлений), КФУ — `kfu_link()` (первое ВИ по плану приёма, 100 баллов —
  где предмет среди ВИ), ВШЭ — `_hse_pages()` (ОП и название по геометрии),
  МГУ — `msu_same_direction()`, СПбГУ — `spbu_rows()` и `spbu_vsosh_rows()`,
  Сеченов — `sechenov_link()` (ВИ из приложения 2), КГМУ — секции документа.
  Не нашли программу — льготы нет: откат на весь факультет или направление
  давал льготы чужим программам (задача #68).

## Известные ограничения

- Правила приёма ИТМО (`pravila_bac1.pdf`, 40 МБ) — скан без текстового слоя;
  перечни олимпиад ИТМО лежат отдельными файлами и разобраны нормально.
- ВсОШ разобрана у 8 вузов из 10; у Сеченова и Казанского ГМУ отдельного
  документа соотнесения предметов ВсОШ направлениям не найдено.
- `budget_places_2026` заполнен у 168 программ из 359; остальные помечены `is_demo`.
  У МФТИ КЦП публикуются на направление целиком, а не на программу внутри него,
  поэтому они тоже помечены `is_demo`.
- 31 программа в B имеет статус `to_check`: строку льгот у вуза найти не удалось.
