# Датасеты навигатора по олимпиадам

Три JSON-датасета по `spec/data_format_spec_4.md` + парсер, который их собирает.
Скоуп: **10 вузов × 4 профильные группы** (ИТ / Физика / Биомед / Экономика),
правила приёма **2026** года, перечень олимпиад — **приказ № 669 от 30.08.2025** (редакция 2025/26).

Состояние на 21.09.2026: **датасеты готовы к использованию**, валидатор проходит
чек-лист раздела 5 спецификации без ошибок.

## Что где лежит

```
datasets/
  data/
    vuz_napravleniya.json          # A — образовательные программы вузов
    vuz_napravlenie_olimpiady.json # B — какие олимпиады принимает каждая программа (22 МБ)
    olimpiady_spravochnik.json     # C — справочник олимпиад (собрал Влад)
    olympiad_index_669.json        # общий справочник: перечень №669 с готовыми olympiad_id
    subject_slugs.json             # таблица 1.3 спеки, достроенная до всех 99 профилей
    missing_in_C.json              # 14 олимпиад, на которые ссылается B, но которых нет в C
    sources_manifest.json          # 72 источника: URL, sha256, дата проверки
  parser/                          # код сборки A и B + README по модулям
  spec/                            # спецификация и справочники вузов/групп
```

Снапшоты источников (85 МБ PDF и HTML) в репозиторий не кладутся — они
воспроизводятся `parser/fetch.py` и сверяются по `sha256` из манифеста.

## Как этим пользоваться в приложении

Связка такая: **`A.program_id` → `B.program_id`**, внутри B каждая льгота несёт
**`olympiad_id` → `C.olympiad_id`**.

```python
import json
A = json.load(open("datasets/data/vuz_napravleniya.json"))["vuz_napravleniya"]
B = json.load(open("datasets/data/vuz_napravlenie_olimpiady.json"))["vuz_napravlenie_olimpiady"]
C = {o["olympiad_id"]: o for o in json.load(open("datasets/data/olimpiady_spravochnik.json"))["olimpiady"]}

# «Какие олимпиады дают БВИ на ИТ-программы ВШЭ»
for prog in B:
    if prog["vuz_id"] != "hse" or prog["profile_group"] != "ИТ":
        continue
    for b in prog["prinimaemye_olimpiady"]:
        if b["benefit_type"] != "БВИ":
            continue
        olymp = C.get(b["olympiad_id"])            # может быть None — см. missing_in_C.json
        print(prog["program_name"], "|", b["olympiad_name_at_vuz"],
              "|", b["diploma_status"], "| ЕГЭ", b["ege_confirm_subject"],
              ">=", b["ege_confirm_min_score"], "|", b["source_url"], b["source_page"])
```

Что важно при выводе пользователю:

- **`ege_confirm_min_score` — не константа 75.** В данных встречаются 75, 77, 80, 85, 90.
  У МФТИ два разных порога: 75 подтверждает «100 баллов», 80–85 подтверждает БВИ.
- **Победитель и призёр — отдельные записи** с одинаковым `olympiad_id`.
  Не схлопывайте их и не выбирайте «более сильную» льготу за пользователя.
- **`is_demo: true`** означает, что факт не подтверждён источником. В интерфейсе
  такие данные обязаны быть помечены — это прямое требование кейса.
- **`source_url` + `source_page`** ведут на конкретную страницу документа.
  Это и есть обещанная «ссылка на первоисточник», показывайте её рядом с льготой.
- **Срок действия диплома — 4 года** — глобальная константа (п. 0.1 спеки),
  в датасетах её нет намеренно, задайте на уровне приложения.
- `C.get(...)` может вернуть `None` для 14 id из `missing_in_C.json` — обработайте.

## Как пересобрать

```bash
pip3 install 'pdfplumber==0.11.10' pypdf lxml pyyaml requests  # 0.11.5 портит текст PDF МГУ
cd datasets
python3 parser/rsr_index.py     # перечень №669 -> общие справочники
python3 parser/fetch.py         # 72 документа -> snapshots/ (10-15 мин, есть задержки)
python3 parser/extract_pdf.py   # PDF/DOCX -> extracted/*.pages.jsonl
python3 parser/build_a.py
python3 parser/build_b.py
python3 parser/validate.py      # код возврата 1, если чек-лист спеки нарушен
```

Самопроверки модулей: `python3 parser/classify.py`, `python3 parser/olymp_match.py`.
Подробности по модулям и ловушкам конкретных вузов — в `parser/README.md`.

## Что важно знать про данные

**Три разные модели льгот**, и схема вмещает все:

1. *По названию* — вуз перечисляет конкретные олимпиады (СПбГУ, ВШЭ, ИТМО, Сеченов, КГМУ).
2. *По профилю* — «любая перечневая олимпиада этого профиля и уровня».
   Так устроены звёздочки у МГУ (сноска: «Все олимпиады школьников соответствующего
   уровня, включенные в Перечень»), приложение 3 КФУ, таблицы НГУ, строки
   «Все из перечня» у ИТМО. Читать их как списки названий — значит потерять
   у МГУ 489 строк из 627.
3. *Матрица* — МФТИ: льгота зависит ещё и от физтех-школы, БВИ даётся не «в вуз»,
   а в конкретную ФПМИ/ФРКТ/ЛФИ.

**Вещи, которые ломают наивную обработку:**

- **Сеченов вообще не даёт БВИ по перечневым олимпиадам** — только 100 баллов.
  Дословно, приложение 5, стр. 1: «Право приема без вступительных испытаний
  по результатам олимпиад школьников Университетом не предоставляется».
- **КФУ с 2026 впервые даёт БВИ** по перечневым (раньше только 100 баллов).
  Логика, перенесённая с правил 2025, даст неверный результат.
- **Иннополис**: льготы по ст. 71 и грантовый конкурс — разные вещи.
  В датасет попали только первые; «освобождение от 1 тура» в гранте льготой не является.
- **Ширина таблиц PDF гуляет.** Одну и ту же таблицу приложения 3 Иннополиса
  pdfplumber отдаёт в 5, 7 или 11 колонок, смотря по странице. Разбор по номеру
  колонки молча терял стр. 8, 9, 11 и 16 — 40 строк, среди них Innopolis Open.
  Ячейки берутся вокруг ячейки уровня (`innopolis_rows()` в `build_b.py`).
  Версия pdfplumber тоже важна: 0.11.5 читает PDF МГУ как «без вступительны
  испытаний», и БВИ МГУ пропадают; датасет собран на 0.11.10.
- **Редакция перечня**: берём 2025/26 (№669). В проекте перечня на 2026/27
  нумерация другая — «Ломоносов» становится № 48 вместо № 50, «Физтех» № 51 вместо № 54.
  Смешивать редакции нельзя: одинаковые id будут указывать на разные олимпиады.
- В спеке «Высшая проба / информатика» приведена как `p669-12-informatika`,
  но в действующем перечне Высшая проба — **№ 8**, то есть `p669-8-informatika`.
  Пример в спеке иллюстративный, номера берём из перечня.

**Как проверялась формула `olympiad_id`:** у МФТИ номер перечня напечатан прямо
в таблице приёма — это независимый эталон. Матчер совпал с ним **144 из 144**.

## Ограничения и что не закрыто

- **31 программа** в B со статусом `to_check` — строку льгот у вуза найти не удалось.
- **ВсОШ нет у Сеченова и Казанского ГМУ** — отдельного документа соотнесения
  предметов ВсОШ направлениям подготовки у них не нашлось.
- **`budget_places_2026` заполнен у 168 программ из 359**, остальные помечены `is_demo`.
  У МФТИ КЦП публикуются на направление целиком, а не на программу внутри него,
  поэтому помечены `is_demo` даже там, где число есть.
- **Правила приёма ИТМО** (`pravila_bac1.pdf`, 40 МБ) — скан без текстового слоя.
  На данные не влияет: перечни олимпиад ИТМО лежат отдельными файлами и разобраны.
- **Скоуп сужен до 4 групп** — это стоило 2670 записей, среди которых были правдивые
  факты (олимпиада по русскому даёт 100 баллов по русскому, а русский входит в ВИ
  любой программы). Сделано ради совпадения границ с датасетом C.
  Откатывается функцией `profile_in_scope()` в `parser/build_b.py`,
  но тогда в C придётся добрать ~107 позиций.
- **Датасет C**: у части олимпиад сроки 2026/27 ещё не опубликованы организаторами,
  такие записи помечены `etapy_status: not_published` и дозаполняются позже.
  23.09.2026 даты дозаполнены у 62 профилей: у 39 календарь целиком, у 23
  (`partial_2026_27`) финал ещё не объявлен. Настоящие даты теперь у 112 профилей из 192.

## Чего в датасетах намеренно нет

- Поля `diploma_valid_years` — это глобальная константа (4 года), не факт о вузе.
- Правил приёма 2027 года — вузы публикуют их до 1 ноября, на момент сборки их не было.
- Профилей олимпиад вне четырёх групп — так же, как и в датасете C.
