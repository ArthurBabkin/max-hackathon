# Датасеты навигатора по олимпиадам

Три JSON-датасета по `spec/data_format_spec_4.md` + парсер, который их собирает.
Скоуп: **10 вузов × 4 профильные группы** (ИТ / Физика / Биомед / Экономика),
правила приёма **2026** года, перечень олимпиад — **приказ № 669 от 30.08.2025** (редакция 2025/26).

Состояние на 27.09.2026: **датасеты готовы к использованию**, валидатор проходит
чек-лист раздела 5 спецификации без ошибок. Вуз — это головной вуз: филиалы
и кампусы в других городах — отдельные вузы, в датасетах их нет (п. 0.9 спеки).

## Что где лежит

```
datasets/
  data/
    vuz_napravleniya.json          # A — образовательные программы вузов
    vuz_napravlenie_olimpiady.json # B — какие олимпиады принимает каждая программа (26 МБ)
    olimpiady_spravochnik.json     # C — справочник олимпиад (собрал Влад)
    olympiad_index_669.json        # общий справочник: перечень №669 с готовыми olympiad_id
    subject_slugs.json             # таблица 1.3 спеки, достроенная до всех 99 профилей
    missing_in_C.json              # 14 олимпиад, на которые ссылается B, но которых нет в C
    sources_manifest.json          # 66 источников: URL, sha256, дата проверки
  parser/                          # код сборки A и B + README по модулям
  spec/                            # спецификация и справочники вузов/групп
```

Снапшоты источников (85 МБ PDF и HTML) в репозиторий не кладутся — они
воспроизводятся `parser/fetch.py` и сверяются по `sha256` из манифеста.

## Как этим пользоваться в приложении

Связка такая: **`A.program_id` → `B.program_id`**, внутри B каждая льгота несёт
**`olympiad_id` → `C.olympiad_id`**.

```python
import json
A = json.load(open("datasets/data/vuz_napravleniya.json"))["vuz_napravleniya"]
B = json.load(open("datasets/data/vuz_napravlenie_olimpiady.json"))["vuz_napravlenie_olimpiady"]
C = {o["olympiad_id"]: o for o in json.load(open("datasets/data/olimpiady_spravochnik.json"))["olimpiady"]}

# «Какие олимпиады дают БВИ на ИТ-программы ВШЭ»
for prog in B:
    if prog["vuz_id"] != "hse" or prog["profile_group"] != "ИТ":
        continue
    for b in prog["prinimaemye_olimpiady"]:
        if b["benefit_type"] != "БВИ":
            continue
        olymp = C.get(b["olympiad_id"])            # может быть None — см. missing_in_C.json
        print(prog["program_name"], "|", b["olympiad_name_at_vuz"],
              "|", b["diploma_status"], "| ЕГЭ", b["ege_confirm_subject"],
              ">=", b["ege_confirm_min_score"], "|", b["source_url"], b["source_page"])
```

Что важно при выводе пользователю:

- **`ege_confirm_min_score` — не константа 75.** В данных встречаются 75, 77, 80, 85, 90.
  У МФТИ два разных порога: 75 подтверждает «100 баллов», 80–85 подтверждает БВИ.
- **Победитель и призёр — отдельные записи** с одинаковым `olympiad_id`.
  Не схлопывайте их и не выбирайте «более сильную» льготу за пользователя.
- **`is_demo: true`** означает, что факт не подтверждён источником. В интерфейсе
  такие данные обязаны быть помечены — это прямое требование кейса.
- **`source_url` + `source_page`** ведут на конкретную страницу документа.
  Это и есть обещанная «ссылка на первоисточник», показывайте её рядом с льготой.
- **Срок действия диплома — 4 года** — глобальная константа (п. 0.1 спеки),
  в датасетах её нет намеренно, задайте на уровне приложения.
- `C.get(...)` может вернуть `None` для 14 id из `missing_in_C.json` — обработайте.

## Как пересобрать

```bash
pip3 install -r parser/requirements.txt  # pdfplumber 0.11.10: 0.11.5 портит текст PDF МГУ
cd datasets
python3 parser/rsr_index.py     # перечень №669 -> общие справочники
python3 parser/fetch.py         # 67 документов -> snapshots/ (10-15 мин, есть задержки)
python3 parser/extract_pdf.py   # PDF/DOCX -> extracted/*.pages.jsonl
python3 parser/build_a.py
python3 parser/build_b.py
python3 parser/validate.py      # код возврата 1, если чек-лист спеки нарушен
```

Самопроверки модулей: `python3 parser/classify.py`, `python3 parser/olymp_match.py`.
Подробности по модулям и ловушкам конкретных вузов — в `parser/README.md`.

## Что важно знать про данные

**Три разные модели льгот**, и схема вмещает все:

1. *По названию* — вуз перечисляет конкретные олимпиады (СПбГУ, ВШЭ, ИТМО, Сеченов, КГМУ).
2. *По профилю* — «любая перечневая олимпиада этого профиля и уровня».
   Так устроены звёздочки у МГУ (сноска: «Все олимпиады школьников соответствующего
   уровня, включенные в Перечень»), приложение 3 КФУ, таблицы НГУ, строки
   «Все из перечня» у ИТМО. Читать их как списки названий — значит потерять
   у МГУ 489 строк из 627.
3. *Матрица* — МФТИ: льгота зависит ещё и от физтех-школы, БВИ даётся не «в вуз»,
   а в конкретную ФПМИ/ФРКТ/ЛФИ.

**Вещи, которые ломают наивную обработку:**

- **Сеченов вообще не даёт БВИ по перечневым олимпиадам** — только 100 баллов.
  Дословно, приложение 5, стр. 1: «Право приема без вступительных испытаний
  по результатам олимпиад школьников Университетом не предоставляется».
- **КФУ с 2026 впервые даёт БВИ** по перечневым (раньше только 100 баллов).
  Логика, перенесённая с правил 2025, даст неверный результат.
- **Иннополис**: льготы по ст. 71 и грантовый конкурс — разные вещи.
  В датасет попали только первые; «освобождение от 1 тура» в гранте льготой не является.
- **Ширина таблиц PDF гуляет.** Одну и ту же таблицу приложения 3 Иннополиса
  pdfplumber отдаёт в 5, 7 или 11 колонок, смотря по странице. Разбор по номеру
  колонки молча терял стр. 8, 9, 11 и 16 — 40 строк, среди них Innopolis Open.
  Ячейки берутся вокруг ячейки уровня (`innopolis_rows()` в `build_b.py`).
  У МГУ профиль, перечень, класс и предмет ЕГЭ — объединённые ячейки на
  несколько уровней («Химия, *: I — …, II — 100 баллов»), у строк-продолжений
  они пустые; без переноса вниз (`msu_rows()`) терялось 88 строк.
  Версия pdfplumber тоже важна: 0.11.5 читает PDF МГУ как «без вступительны
  испытаний», и БВИ МГУ пропадают; датасет собран на 0.11.10.
- **Редакция перечня**: берём 2025/26 (№669). В проекте перечня на 2026/27
  нумерация другая — «Ломоносов» становится № 48 вместо № 50, «Физтех» № 51 вместо № 54.
  Смешивать редакции нельзя: одинаковые id будут указывать на разные олимпиады.
- В спеке «Высшая проба / информатика» приведена как `p669-12-informatika`,
  но в действующем перечне Высшая проба — **№ 8**, то есть `p669-8-informatika`.
  Пример в спеке иллюстративный, номера берём из перечня.

**Льгота — только программам, которых она касается.** Каждый вуз адресует
льготу по-своему, и откат «не нашли — отдать всем» даёт ложные льготы (так ВсОШ
по биологии попадала на ПМИ МГУ, задача #68):

- МФТИ — физтех-школа по позиции колонки в заголовке и конкурсные группы в
  кавычках («Все конкурсные группы ФБМФ» — без ВШБИ); по ВсОШ, кроме БВИ, —
  100 баллов в тех же группах по предмету из таблицы п. 8 («Экономика» ->
  математика, «Астрономия» -> физика), где он среди ВИ программы;
- ИТМО — колонка направления и «(учитывается только на программе …)»;
- КФУ — «на все направления, где ВИ … являются первыми в Плане приема»: БВИ,
  если предмет олимпиады — первое ВИ программы (план приёма — приложение 1),
  и 100 баллов, если он среди ВИ, но не первое (приложение 3, стр. 1–2);
  код без «(профиль: …)» — все программы направления, ВИ не проверяются;
  код, которого у КФУ нет, — опечатка, если профиль дословно равен программе
  (стр. 24: 15.03.01 вместо 15.03.06); перечни прошлых лет (стр. 39–125) не
  читаются — у них своя нумерация;
- ВШЭ — ОП и название олимпиады берутся по геометрии PDF: это объединённые
  ячейки, чей текст таблица теряет; статус, предмет и порог ЕГЭ — объединённые
  ячейки на строки БВИ и 100 баллов; строка без ОП в направлении, где ОП
  названы, пропускается;
- название олимпиады -> номер перечня: общие слова («олимпиада школьников») не
  засчитываются, иначе Кондратьевская и «Газпром» становились Московской;
- МГУ — направление совпадает точно, уточнение (группа программ, профиль)
  обязано совпасть; секции «… (ФАКУЛЬТЕТ)» — те же высшие школы, что в A;
  уровни у «*» — множество («I, III» без II); льгота — тоже объединённая
  ячейка; олимпиады экономфака — через «;». ВсОШ: 100 баллов ЕГЭ по предмету
  (п. 26 Правил) на программы, где он ВИ по плану приёма, если БВИ нет;
- СПбГУ — «—» в перечне РСОШ означает «любая олимпиада уровня с профилем или
  предметом»; предмет или УГН сравнивается с графой перечня точно («Математика» —
  не УГН «математика и механика»); предмет и порог ЕГЭ — объединённые ячейки ВИ,
  классы — 10 или 11 из шапки. ВсОШ: БВИ — из отдельного документа, 100 баллов
  за ВИ — по приложению 7 Правил там, где БВИ нет;
- ИТМО — уровень в перечнях — точное множество («2 или 3» — не I); 100 баллов
  (приложение 6) — только по дипломам, которые не дают БВИ; классы — 10 или 11
  из заголовков приложений;
- Иннополис — БВИ на направления графы 3 приложения 3 (п. 61 а) Правил): если
  там только УГСН без ИВТ, на 09.03.01 — лишь 100 баллов по графе 5; '' в
  ячейке названия внизу страницы — начало новой объединённой ячейки;
- Сеченов — 100 баллов только программам, где предмет — среди ВИ
  (приложение 2). Графы приложения 5 — по заголовку таблицы: ширина гуляет
  (8–16 колонок), значение бывает задвоено внутри графы; названия и профили
  в несколько строк дописываются целиком. Профиль, который вуз оборвал
  («виртуальные миры: …» без «цифровые технологии в архитектуре»), берётся
  полным, если у этой олимпиады он по такому началу один. КГМУ — только
  специальностям своей секции.

`validate.py` сверяет B с эталонными фактами, выписанными из первоисточников
вручную, и падает, если льгота снова ушла чужой программе; в CI его гоняет
`test_validate.py`.

**Как проверялась формула `olympiad_id`:** у МФТИ номер перечня напечатан прямо
в таблице приёма — это независимый эталон. Матчер совпал с ним **144 из 144**.

## Ограничения и что не закрыто

- **Льгота зависит от класса диплома** (ВШЭ, «Будущее Сибири» по физике: БВИ за
  11 класс, 100 баллов за 10-й) — в B это разные записи с `eligible_grades`, а сид
  сворачивает их в одну строку на вуз: классы — у лучшей льготы, остальное — в примечании.
- **Сеченов, «Ломоносов» — робототехника**: у №50 в перечне такого профиля нет,
  строка не привязана.
- **ВсОШ у Сеченова и Казанского ГМУ** — не в перечне олимпиад, а в правилах
  приёма: таблица «код — специальность — профили ВсОШ» (Сеченов, Правила стр. 13;
  КГМУ, «Информация о предоставлении особых прав» стр. 2). 100 баллов по ВсОШ
  у Сеченова — по таблице п. 5.3 (стр. 14), там, где предмет среди ВИ программы.
- **`budget_places_2026` заполнен у 136 программ из 275**, остальные помечены `is_demo`.
  У МФТИ КЦП публикуются на направление целиком, а не на программу внутри него,
  поэтому помечены `is_demo` даже там, где число есть.
- **Правила приёма ИТМО** (`pravila_bac1.pdf`, 40 МБ) — скан без текстового слоя.
  На данные не влияет: перечни олимпиад ИТМО лежат отдельными файлами и разобраны.
- **Граница B — каталог продукта**: олимпиады датасета C и `missing_in_C.json`
  (`in_catalog()` в `parser/build_b.py`). Олимпиады вне каталога сид не знает,
  поэтому их льготы в B не пишутся: так теряются правдивые факты вроде «олимпиада
  по русскому даёт 100 баллов по русскому». Вернуть их — добрать олимпиады в C.
- **Датасет C**: у части олимпиад сроки 2026/27 ещё не опубликованы организаторами,
  такие записи помечены `etapy_status: not_published` и дозаполняются позже.
  23.09.2026 даты дозаполнены у 62 профилей: у 39 календарь целиком, у 23
  (`partial_2026_27`) финал ещё не объявлен. Настоящие даты теперь у 112 профилей из 192.

## Методология сбора и обновления

**Что считаем вузом.** Головную организацию с её правилами приёма и местами:
кампусы ВШЭ вне Москвы, филиалы МГУ, институты-филиалы КФУ, филиалы Сеченова —
другие вузы, хотя и называются так же. Нужен филиал — это новый `vuz_id` в
`spec/vuzy_catalog.json`, а не программы внутри головного. Конкурсные группы для
иностранных граждан не берём: это не наша аудитория.

**Где задан скоуп.** В трёх местах, и они должны совпадать:

1. `parser/sources.yaml` — только документы головного вуза.
2. Парсер отбрасывает секцию филиала по её шапке («филиал», «… ФГАОУ ВО …»),
   а не по номеру страницы: страницы съезжают с каждой редакцией документа.
3. `parser/validate.py` падает, если `faculty` называет филиал или в названии
   программы есть «иностранных граждан». В CI его гоняет `test_validate.py`.

**Цикл обновления.** Раз в год — когда вузы публикуют правила следующего
приёма (до 1 ноября), и точечно, когда вуз меняет документ:

1. `fetch.py` — скачать документы; изменившиеся видны по `sha256` в манифесте.
2. `extract_pdf.py`, `build_a.py`, `build_b.py` — собрать A и B.
3. `validate.py` — чек-лист и эталонные факты. Новый факт, сверенный с
   документом, добавляется в `GOLDEN` вместе со страницей и цитатой.
4. `make seed` — сиды `0003` и `0021`; `diff_seed.py --base origin/master` —
   миграция-разница для накатанных баз. Источник, на который ссылается
   миграция после сида, сид держит сам (`keep_later_sources()`), иначе на
   чистой базе она упадёт на внешнем ключе.
5. `make test-db` — после всех миграций база равна сиду, повторный прогон
   ничего не меняет.
6. PR со сводкой «что поменялось у каких вузов» и с числом событий, которые
   получат семьи (триггер `0006`).

**Что в формате неудобно и пока не меняем.** B развёрнут до записи на каждую
пару «программа × олимпиада × статус»: 38 814 записей, из которых уникальных
фактов уровня вуза около 5 100, а URL источника повторяется в каждой. Правила
«любая олимпиада профиля» (МГУ, КФУ, НГУ, ИТМО) хранятся развёрткой, поэтому
новая олимпиада в C требует пересборки B. `program_id` — слаг названия с
суффиксом по порядку обхода, и он сдвигается, если рядом появилась программа
с тем же названием. Снапшоты не в git, так что пересобрать тот же результат
может только тот, у кого они лежат. Когда это начнёт мешать: снапшоты — в
общий бакет по `sha256`, B — правилами вуза, которые разворачивает генератор сида.

## Чего в датасетах намеренно нет

- Поля `diploma_valid_years` — это глобальная константа (4 года), не факт о вузе.
- Правил приёма 2027 года — вузы публикуют их до 1 ноября, на момент сборки их не было.
- Профилей олимпиад вне четырёх групп — так же, как и в датасете C.
