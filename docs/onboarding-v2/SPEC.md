# Онбординг v2 — спецификация

Документ описывает целевое поведение. Где сказано «сейчас» — это состояние кода
на коммите `fed2d26` (ветка `chore/dev-bot-script`, поверх `master` = `1c3d19c`).
Коды экранов (`R1`, `A2`…) — артборды на холсте, см. [README](README.md).

**Короткая анкета (#127).** Анкета сокращена до пяти шагов: роль (и имя) →
класс → предметы → направления → вузы → итог. Регион (3), опыт (6), «Где
учиться» (7), подтверждение имени ученика и карточку профиля (9.1–9.2) убрали:
они почти не влияют на подбор, а поменять их можно в профиле мини-приложения.
Почему — [DECISIONS](DECISIONS.md), «Короткая анкета». Разделы ниже описывают
поведение после #127; убранное оставлено короткой справкой.

## 0. Общие правила

- **Два голоса.** Любой новый текст — ключ в `packages/shared/texts/texts.json`
  с вариантами `kid` и `parent` (F3). Ученику на «ты», родителю на «вы» и о
  ребёнке по имени: `{student}`, `{student_gen}`, `{student_dat}` (см.
  `packages/core/voice`). Тексты ниже — точные, менять можно только опечатки.
- **Род не угадываем.** Имя ученика не говорит о поле, поэтому формулировки
  нейтральные: «Какой у тебя опыт в олимпиадах?», а не «Ты участвовал?».
- **Названия мест не склоняем.** Кнопки и тексты используют именительный
  падеж: «Только Набережные Челны», «Весь регион · Татарстан».
- **Счётчик шагов.** Первая строка каждого вопроса онбординга — «Шаг N из 5»
  (`bot.step`), затем пустая строка. Роль и имя 1 (имя — часть шага «кто
  вы»), класс 2, предметы 3, направление 4 (вместе с В1, В2 и `suggest`),
  вузы 5. У приглашённого ребёнка (`Draft.Joined`) счётчика нет.
- **Имя.** Ученику имя берётся из профиля MAX без вопроса. Шаг `name_input`
  — у родителя (имя ребёнка) и у ученика, у которого в MAX имени нет (бот
  тогда зовёт его «Друг», `anonName`, и это имя в траекторию не пишет).
- **Шаг — условие перехода.** Как сейчас: нажатие кнопки из старого сообщения
  не меняет диалог (`ErrStale` → `b.stale`). Мультивыбор правит клавиатуру на
  месте (`transition`).
- **«← Назад» на каждом шаге**, кроме первого (роль) и шагов приглашённого
  (`interest` у `Joined`, `join_*`). Последний ряд клавиатуры, `bot.btn.back`,
  payload `back:<шаг>` — со старого вопроса ничего не меняет. Нажатие правит
  текущий вопрос на месте: вместо него — предыдущий. Черновик не трогается,
  ответы отмечены «✓», и вперёд их можно пройти, ничего не выбирая заново:
  мультивыбор — «Готово»; класс, роль, В2 — та же кнопка с «✓»; введённое
  имя — кнопка `[✓ Артём]` (`name:keep`). Та же роль после «Назад» сохраняет
  имя, другая — сбрасывает (у родителя это имя ребёнка). Куда ведёт «Назад»
  (`backStep`):

  | Шаг | Назад |
  |---|---|
  | `name_input` | `role` |
  | `grade` | `name_input` (родитель или ученик без имени в MAX) или `role` |
  | `subjects` → `direction` | предыдущий по порядку |
  | `interest` → `work` → `suggest` | `direction` → `interest` → `work` |
  | `universities` | `suggest`, если направления предложены по интересам, иначе `direction` |

  Выбор на шаге `direction` («Готово», «Решу позже») снимает предложенные
  (`Suggested`) и «Пусть ребёнок ответит».
- **Кнопок «неактивно» в MAX нет.** Недоступная функция — обычная callback-
  кнопка, ответ на неё — `CallbackAnswer{Notification: …}`.
- **Лимиты MAX:** до 7 кнопок в ряду (до 3 для geo/link/open_app), до 30 рядов,
  210 кнопок; payload callback до 1024 байт (`maxapi/keyboard.go`). Payload
  держим коротким: `вид:действие:аргумент`.
- **Свободный текст** обрабатывает `freeText`: на шаге `name_input` это имя,
  на `universities` — поиск вуза (8.2). На убранном шаге (1.3) — следующий
  вопрос, на остальных — подсказка.
- **Скоринг детерминированный**, без LLM. LLM (Jev) — только TODO в разделе 5.4.
- **Markdown:** `maxapi.NewMessage` поддерживает `Format: "markdown"`, для
  итога это нужно.

### 1.2. `trajectory_places` (новая)

```sql

    trajectory_id uuid NOT NULL REFERENCES trajectories(id) ON DELETE CASCADE,
    position      smallint NOT NULL,

    city          text,          -- NULL — весь регион

INSERT INTO trajectory_places (trajectory_id, position, region_code)
SELECT id, 0, target_region_code FROM trajectories WHERE target_region_code IS NOT NULL;
```

## 2. Скоринг (`packages/core/match`, `packages/core/pick`)

Все изменения покрыть тестами в `match_test.go` / новых тестах `pick`.

### 2.1. Вес уровня по опыту

`levelValue[уровень]` → `levelValue[опыт][уровень]`. `match.Student` получает
`Experience string`. ВсОШ сейчас считается как I уровень — оставить так для
`region`, для `none`/`school` считать как II (школьный этап ВсОШ доступен всем).

```
             I     II    III
none        0.4   0.8   1.0
school      0.7   1.0   0.6
region      1.0   0.6   0.3
```

Пустой опыт = `none`.

### 2.2. Вес льготы по классу

`w.Benefit` умножается на `benefitGradeFactor`: 10–11 класс — `1.0`, 8–9 —
`0.5`. Причина: у многих вузов диплом засчитывается только за 10–11 класс
(`benefits.diploma_grades`). Если хватит времени — вместо множителя учитывать
`diploma_grades` явно (не обязательно).

### 2.3. «Потенциальная» льгота

Сейчас при пустом списке вузов фактор Benefit = 0 у всех. Новое: если у
траектории нет вузов, `BestBenefit` считается по вузам, у которых есть хотя бы
одно направление траектории (для `exploring` — любые вузы), в выбранных местах
(`trajectory_places`; нет мест — везде). В `pick.Candidate` добавить
`PotentialBenefit bool`, чтобы причина звучала иначе (раздел 2.5).

### 2.4. Разнообразие

После сортировки перечня и `bestPerOlympiad`: в топ-5 не больше **2 олимпиад
на один `SubjectCode`**. Лишние сдвигаются вниз, освободившиеся места
занимают следующие по скору.

### 2.5. Причины

Новые варианты в `texts.json` (фронт показывает причину по Top-факторам):

| Ключ | kid | parent |
|---|---|---|
| `reason.levelFit` | Подходит под твой опыт | Подходит под опыт {student_gen} |
| `reason.benefitPotential` | Даёт льготу в вузах по направлению | Даёт льготу в вузах по направлению |

`reason.levelFit` используется вместо `reason.levelI/II/III`, когда опыт задан и
вклад уровня ≥ 0.8 от максимума. `reason.benefitPotential` — когда льгота
потенциальная.

### 2.6. Стартовая олимпиада для итога

`pick.Start(res Result) *match.Result` — первая из `res.Items` по **скору** (не
по сроку), у которой ближайший срок не раньше чем через 1 день. ВсОШ не
выбирается стартовой, если опыт `none` и есть олимпиады перечня.

## 3. Регион (экраны R1–R5)

Убран из анкеты в #127. Траектория создаётся с `region_code = ''` и
`tz = Europe/Moscow` (`refdata.DefaultTZ`): напоминания по московскому
времени, в профиле бота «Класс: 9» без места (`bot.summary.gradeOnly`). Регион
меняется в профиле мини-приложения (`PATCH /profile`, `region_code`; пустой —
«Не указан»). Геопозицию бот не разбирает: ответ как на непонятное сообщение.
Поиск мест (`refdata.Search`, `places.json`, `aliases.json`) в боте больше не
используется.

### 5.2. Шаг `interest` — В1 (A2)

`bot.interest.ask`:
kid — «Два вопроса про интересы. Что из этого тебе нравится больше всего? Можно два варианта.»
parent — «Два вопроса про интересы. Что из этого больше всего нравится {student_dat}? Можно два варианта.»

Мультивыбор, максимум 2 (третье нажатие → уведомление `bot.interest.max`:
«Можно выбрать два варианта» / то же). «Готово» от одного
(`bot.interest.need`: «Выбери хотя бы один вариант» / «Выберите хотя бы один вариант»).

| Код | Кнопка (оба голоса) |
|---|---|
| `code` | Писать код, делать игры и программы |
| `tasks` | Решать сложные задачи и головоломки |
| `world` | Разбираться, как устроен мир, ставить опыты |
| `bio` | Живая природа, медицина, организм |
| `society` | Деньги, бизнес, как устроено общество |

Payload `int:t:<код>`, `int:done`.

### 5.4. Подсчёт направлений

Функция `suggestDirections(interests []string, work string, subjects []string, dirs []store.Direction) []string` в `apps/bot` (или `packages/core/pick`), чистая, с тестами.

`score(dir) = Σ interestWeight[код][dir] + workWeight[код][dir] + 1 за каждый любимый предмет в dir.SubjectCodes`.

| Направление (id) | Интересы (вес) | Работа (вес) |
|---|---|---|
| `napr-09-03-04` Программная инженерия | code 2, tasks 1 | build 2 |
| `napr-01-03-02` ПМИ | code 1, tasks 2 | research 1, build 1 |
| `napr-09-03-01` ИВТ | code 2, world 1 | build 2 |
| `napr-10-03-01` Информационная безопасность | code 2, tasks 1 | build 1 |
| `napr-03-03-02` Физика | world 2, tasks 1 | research 2 |
| `napr-03-03-01` Прикладные математика и физика | tasks 2, world 2 | research 2 |
| `napr-03-05-01` Астрономия | world 2 | research 2 |
| `napr-16-03-01` Техническая физика | world 2 | build 2 |
| `napr-31-05-01` Лечебное дело | bio 2 | health 2 |
| `napr-19-03-01` Биотехнология | bio 2, world 1 | build 1, research 1 |
| `napr-33-05-01` Фармация | bio 2 | health 1, research 1 |
| `napr-06-03-01` Биология | bio 2, world 1 | research 2 |
| `napr-38-03-01` Экономика | society 2, tasks 1 | manage 1, research 1 |
| `napr-38-03-02` Менеджмент | society 2 | manage 2 |
| `napr-38-03-05` Бизнес-информатика | society 1, code 1 | manage 1, build 1 |
| `napr-38-03-04` ГМУ | society 2 | manage 2 |

Берём до 3 с наибольшим счётом и счётом ≥ 3; если таких меньше 2 — два лучших
с ненулевым счётом. Равенство — порядок справочника. Направление без веса в
таблице (новое в справочнике) получает только баллы за предметы.

### 5.5. Шаг `suggest` (A3)

`bot.suggest.ask`: kid — «Похоже, тебе подойдут эти направления. Я их отметил — сними лишнее или добавь своё.»
parent — «Похоже, {student_dat} подойдут эти направления. Я их отметил — снимите лишнее или добавьте своё.»

Клавиатура как на шаге `direction`, предложенные уже с «✓» (`DirectionIDs =
Suggested`), плюс `[Показать все направления]`, `[Готово]`,
`[Всё равно не знаю]` / `[Всё равно не знаем]` (`dir:later`). Payload те же
`dir:*`. «Готово» → `goal_status = suggested`, шаг `universities`.

Строка «почему» под вопросом (A3) — по желанию, не обязательно.

## 6. Опыт (экраны B1, P2)

Убран из анкеты в #127. `experience = NULL`, подбор считает его как `none`
(«первые олимпиады», 2.1): стартовой чаще становится олимпиада III уровня.
Опыт меняется в профиле мини-приложения. В профиле бота строка «Опыт» есть,
только если опыт указан (старые траектории): `none` — «первые олимпиады»,
`school` — «школьный или муниципальный этап», `region` — «региональный этап
и выше».

## 7. Где учиться (экраны W1–W3)

Убран из анкеты в #127. Мест нет — «не важно»: подборка вузов в боте и
потенциальная льгота (2.3) не ограничены местом. Места меняются в профиле
мини-приложения, при создании траектории — `trajectory_places`, если их

## 8. Вузы (экраны V1–V3)

### 8.1. Подборка (V1)

`bot.vuz.ask`: kid — «Вот вузы с направлениями {directions}. Отметь, куда хочешь поступать, — покажу льготы именно в них. Или напиши название вуза.»
parent — «Вот вузы с направлениями {directions}. Отметьте, куда хочет поступать {student}, — покажу льготы именно в них. Или напишите название вуза.»
`{directions}` — названия через запятую со строчной буквы. Без направлений —
`bot.vuz.askAny`: kid «Куда хочешь поступать? Отметь вузы — покажу льготы
именно в них. Или напиши название вуза.», parent «Куда хочет поступать
{student}? Отметьте вузы — …».

Кнопки `«{short_name} · {city}»`, до 6, по 2 в ряд, payload `vuz:t:<id>`.
Отбор — `SuggestUniversities(directionIDs, nil, limit, offset)`: вузы с
выбранными направлениями (без направлений — все), сначала те, где совпало
больше. Дальше `[Показать ещё]` (`vuz:more`, следующие 6), последняя кнопка
анкеты (`vuz:done`) и `[← Назад]`. Последняя кнопка — `[Готово]`, если вуз
отмечен, иначе `bot.vuz.later` «Выберу позже» / «Выберем позже». Обе сразу
создают траекторию и присылают итог (9.3). Вузов с направлениями нет —
`bot.vuz.none`: «Вузов с этими направлениями в базе пока нет. Напиши название
вуза или выбери позже в мини-приложении.» / «…Напишите… выберите…».

### 8.2. Поиск по названию (V2)

Текст на шаге `universities` → поиск по `short_name`, `name` и алиасам
(новый словарь `universityAliases` в `apps/bot` или `refdata`): `вышка, вшэ →
hse`; `мгу → msu`; `спбгу, питерский университет → spbu`; `физтех, мфти →
mipt`; `итмо → itmo`; `нгу → nsu`; `кфу, казанский федеральный → kfu`;
`иннополис, уи → innopolis`; `сеченовка, первый мед → sechenov`; `кгму,
казанский медицинский → kazan-gmu`. Найденный вуз добавляется с «✓».

Кампусы (у ВШЭ Москва / СПб / Нижний Новгород / Пермь) — **только если в базе
появятся данные о кампусах** (сейчас у вуза один город). Тогда ответ
`bot.vuz.campus`: «У {uni} несколько кампусов с нужными направлениями. Какой?»
и кнопки `«{uni} · {город}»` + `[Все кампусы]`. Без данных — не делать.

Ничего не найдено — `bot.vuz.notFound`: «Не нашёл вуз «{query}». Попробуй
иначе или выбери из списка.» / «…Попробуйте…».

### 8.3. Нет направления в выбранных местах (V3)

Убрано в #127 вместе с местами: подборка не ограничена местом, пустой она
бывает, только если вузов с направлениями нет в базе (8.1, `bot.vuz.none`).

### 8.4. Выбрать позже

Вузы не обязательны: «Выберу позже» создаёт траекторию без вузов, в подборе
включается потенциальная льгота (2.3) — без цели по всем вузам. Отметить вузы
можно в профиле мини-приложения.

## 9. Итог (экраны B2, B3)

Пользователь ещё ни разу не открывал мини-приложение и не проходил обучение.
Поэтому итог ведёт в приложение одной кнопкой.

### 9.1. Карточка профиля и 9.2. «Изменить»

Убраны в #127: ответы видны на кнопках с «✓», поправить их можно «← Назад»
до конца анкеты или в профиле мини-приложения. Траектория создаётся
последней кнопкой шага вузов.

### 9.3. «Готово» — итог

`vuz:done` («Готово» или «Выберу позже») создаёт траекторию
(`createTrajectory`) и присылает одно сообщение. Первая строка — число олимпиад подбора
(`pick.Recommend`, фильтр `all`): `bot.result.one` / `many` — «Под твою цель
подходят 5 олимпиад и ВсОШ.», без цели — `oneSubjects` / `manySubjects` «По
твоим предметам подходят…». Ничего не нашлось — `bot.result.empty`.

Затем стартовая олимпиада из `pick.Start` (2.6):
`bot.result.start`: kid — «Для старта советую эту:», parent — «Для старта советую {student_dat} эту:»; следом отдельными строками
`{olympiad} · {subject}` и `{level} уровень · до {date}, {days} · онлайн`
(«онлайн» — если отбор онлайн).

Следом тем же видом — ближайшая по сроку олимпиада подбора (самый ранний
срок, до которого ещё есть хотя бы день): `bot.result.nearest` «Ближайшая
олимпиада:» (оба голоса). Если стартовая и есть ближайшая, блок один:
`bot.result.startNearest` — kid «Для старта советую эту — она же ближайшая:»,
parent «Для старта советую {student_dat} эту — она же ближайшая:». Затем
`bot.result.tail` / `tailNoVuz`.

Кнопка одна: `[Открыть «Траекторию»]` — `open_app` с `start_param=home`,
новичку мини-приложение показывает обучение. Напоминаний и приглашения в
итоге нет: о трекере и семье рассказывает обучение.

Исключение — родитель нажал «Пусть ответит {student}» (10): первой идёт
`[👋 Пригласить {student_acc}]`, в тексте — `bot.result.kidInvite`.

Приглашённым (родителю сразу, ребёнку после «Всё верно») — тот же итог,
ребёнку с «Отлично!» в начале.

## 10. Родитель и приглашённый ребёнок (экраны P1–P3)

- Все шаги — те же, голос parent. Отличия: имя ребёнка (`name_input`),
  `dir:kid` (5.1).
- `GoalByKid = true` → в итоге (9) приглашение предлагается первым: кнопка
  `[Пригласить {student_gen}]` идёт первой строкой, над ней фраза
  `bot.result.kidInvite` (parent): «Отправьте ссылку {student_dat}: ответы
  про интересы уточнят подборку.»
- **Приглашённый ребёнок (P3).** `joinCheck` показывает профиль списком
  (`profileLines`): класс и место, предметы, цель; опыт, места и вузы — если
  есть. Если у траектории нет направлений
  и `goal_by_kid = true` — после «Всё верно» бот не предлагает список
  направлений (`join_direction`), а ведёт по `interest → work → suggest`
  (голос kid), затем `SetDirections`, `goal_by_kid = false`,
  `goal_status = suggested`. Родителю — уведомление
  `bot.notify.kidChoseGoal` (parent): «{student}: цель выбрана —
  {directions}. Подборка обновлена.»
- Если `goal_by_kid = false` — как сейчас (F42).
