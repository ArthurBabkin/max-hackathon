# Онбординг v2 — спецификация

Документ описывает целевое поведение. Где сказано «сейчас» — это состояние кода
на коммите `fed2d26` (ветка `chore/dev-bot-script`, поверх `master` = `1c3d19c`).
Коды экранов (`R1`, `A2`…) — артборды на холсте, см. [README](README.md).

## 0. Общие правила

- **Два голоса.** Любой новый текст — ключ в `packages/shared/texts/texts.json`
  с вариантами `kid` и `parent` (F3). Ученику на «ты», родителю на «вы» и о
  ребёнке по имени: `{student}`, `{student_gen}`, `{student_dat}` (см.
  `packages/core/voice`). Тексты ниже — точные, менять можно только опечатки.
- **Род не угадываем.** Имя ученика не говорит о поле, поэтому формулировки
  нейтральные: «Какой у тебя опыт в олимпиадах?», а не «Ты участвовал?».
- **Названия мест не склоняем.** Кнопки и тексты используют именительный
  падеж: «Только Набережные Челны», «Весь регион · Татарстан».
- **Счётчик шагов.** Первая строка каждого вопроса онбординга — «Шаг N из 9»
  (`bot.step`), затем пустая строка. Номера постоянные: роль 1, имя 2, класс 3,
  регион 4, предметы 5, направление 6 (вместе с В1, В2 и `suggest`), опыт 7,
  «Где учиться» 8, вузы 9. Пропущенный шаг не сдвигает номера: счётчик
  перескакивает. У приглашённого ребёнка (`Draft.Joined`) и при правке из
  карточки профиля (раздел 9) счётчика нет.
- **Шаг — условие перехода.** Как сейчас: нажатие кнопки из старого сообщения
  не меняет диалог (`ErrStale` → `b.stale`). Мультивыбор правит клавиатуру на
  месте (`transition`).
- **«← Назад» на каждом шаге**, кроме первого (роль) и шагов приглашённого
  (`interest` у `Joined`, `join_*`). Последний ряд клавиатуры, `bot.btn.back`,
  payload `back:<шаг>` — со старого вопроса ничего не меняет. Нажатие правит
  текущий вопрос на месте: вместо него — предыдущий. Черновик не трогается,
  ответы отмечены «✓», и вперёд их можно пройти, ничего не выбирая заново:
  мультивыбор — «Готово»; класс, роль, В2, опыт — та же кнопка с «✓»; имя
  родителя — кнопка `[✓ Артём]` (`name:keep`); регион — первая кнопка
  `[✓ Казань · Татарстан]` (`region:keep`) или `[✓ Не важно]`
  (`Draft.RegionAny`). Та же роль после «Назад» сохраняет имя, другая —
  сбрасывает (у родителя это имя ребёнка). Куда ведёт «Назад» (`backStep`):

  | Шаг | Назад |
  |---|---|
  | `name_confirm` | `role` |
  | `name_input` | `name_confirm` (ученик с именем в MAX) или `role` |
  | `grade` | `name_confirm` (ученик с именем в MAX) или `name_input` |
  | `region` → `subjects` → `direction` | предыдущий по порядку |
  | `interest` → `work` → `suggest` | `direction` → `interest` → `work` |
  | `experience` | `suggest`, если направления предложены по интересам, иначе `direction` |
  | `target` | `experience` |
  | `universities` | `target` |

  Выбор на шаге `direction` («Готово», «Решу позже») снимает предложенные
  (`Suggested`) и «Пусть ребёнок ответит». Места, добавленные текстом,
  остаются на кнопках «Где учиться» и после возврата к опыту
  (`targetOptions`).
  При правке из карточки профиля (9.2) «Назад» ведёт к меню «Что поменять?»
  (`EditMenu`), ответ правленого поля остаётся прежним; внутри поля
  («Помоги выбрать» у направлений) — к его прошлому вопросу.
- **Кнопок «неактивно» в MAX нет.** Недоступная функция — обычная callback-
  кнопка, ответ на неё — `CallbackAnswer{Notification: …}`.
- **Лимиты MAX:** до 7 кнопок в ряду (до 3 для geo/link/open_app), до 30 рядов,
  210 кнопок; payload callback до 1024 байт (`maxapi/keyboard.go`). Payload
  держим коротким: `вид:действие:аргумент`.
- **Свободный текст** обрабатывает `freeText`: на шагах `region`, `target`,
  `universities` он становится поиском (разделы 3, 7, 8). На остальных шагах —
  как сейчас, подсказка.
- **Скоринг детерминированный**, без LLM. LLM (Jev) — только TODO в разделе 5.4.
- **Markdown:** `maxapi.NewMessage` поддерживает `Format: "markdown"`, для
  итога это нужно.

## 2. Скоринг (`packages/core/match`, `packages/core/pick`)

Все изменения покрыть тестами в `match_test.go` / новых тестах `pick`.

### 2.1. Вес уровня по опыту

`levelValue[уровень]` → `levelValue[опыт][уровень]`. `match.Student` получает
`Experience string`. ВсОШ сейчас считается как I уровень — оставить так для
`region`, для `none`/`school` считать как II (школьный этап ВсОШ доступен всем).

```
             I     II    III
none        0.4   0.8   1.0
school      0.7   1.0   0.6
region      1.0   0.6   0.3
```

Пустой опыт = `none`.

### 2.2. Вес льготы по классу

`w.Benefit` умножается на `benefitGradeFactor`: 10–11 класс — `1.0`, 8–9 —
`0.5`. Причина: у многих вузов диплом засчитывается только за 10–11 класс
(`benefits.diploma_grades`). Если хватит времени — вместо множителя учитывать
`diploma_grades` явно (не обязательно).

### 2.3. «Потенциальная» льгота

Сейчас при пустом списке вузов фактор Benefit = 0 у всех. Новое: если у
траектории нет вузов, `BestBenefit` считается по вузам, у которых есть хотя бы
одно направление траектории (для `exploring` — любые вузы), в выбранных местах
(`trajectory_places`; нет мест — везде). В `pick.Candidate` добавить
`PotentialBenefit bool`, чтобы причина звучала иначе (раздел 2.5).

### 2.4. Разнообразие

После сортировки перечня и `bestPerOlympiad`: в топ-5 не больше **2 олимпиад
на один `SubjectCode`**. Лишние сдвигаются вниз, освободившиеся места
занимают следующие по скору.

### 2.5. Причины

Новые варианты в `texts.json` (фронт показывает причину по Top-факторам):

| Ключ | kid | parent |
|---|---|---|
| `reason.levelFit` | Подходит под твой опыт | Подходит под опыт {student_gen} |
| `reason.benefitPotential` | Даёт льготу в вузах по направлению | Даёт льготу в вузах по направлению |

`reason.levelFit` используется вместо `reason.levelI/II/III`, когда опыт задан и
вклад уровня ≥ 0.8 от максимума. `reason.benefitPotential` — когда льгота
потенциальная.

### 2.6. Стартовая олимпиада для итога

`pick.Start(res Result) *match.Result` — первая из `res.Items` по **скору** (не
по сроку), у которой ближайший срок не раньше чем через 1 день. ВсОШ не
выбирается стартовой, если опыт `none` и есть олимпиады перечня.

## 3. Регион (экраны R1–R5)

### 3.1. Поиск (`packages/core/refdata`)

**Данные.**

- `places.json` — города России из [hflabs/city](https://github.com/hflabs/city)
  (CC BY-SA 4.0): `name`, `region_code` (двузначный, как в `regions.json`),
  `population`, `lat`, `lon`. Генерирует скрипт
  `datasets/parser/build_places.py` из скачанного `city.csv` (сам CSV в репо не
  кладём, JSON — кладём). Атрибуцию дописать в README → «Зависимости и
  лицензии». Новые субъекты (ДНР, ЛНР, Запорожская, Херсонская области) в
  наборе могут отсутствовать — их находит поиск по названию региона.
- `aliases.json` — вручную: `питер, спб → 78`; `мск → 77`; `подмосковье, мо → 50`;
  `екб, екат → Екатеринбург`; `нск → Новосибирск`; `нижний → Нижний Новгород`;
  `башкирия → 02`; `якутия → 14`; `чувашия → 21`; `удмуртия → 18`;
  `осетия → 15`; `кбр → 07`; `кчр → 09`; `хмао, югра → 86`; `янао → 89`;
  `кузбасс → 42`; `рт → 16`; `крым → 91`. Коды сверить с `regions.json`.

**Нормализация запроса:** нижний регистр, `ё → е`, пунктуация → пробел,
выкинуть слова `г`, `город`, `республика`, `область`, `обл`, `край`,
`автономный`, `округ`, `ао`, лишние пробелы. Так же нормализуются названия в
словаре.

**Порядок поиска** — `func Search(q string, limit int) []Match`:

1. точное совпадение (регион, алиас, город);
2. совпадение по началу слова, от 3 символов;
3. подстрока;
4. нечёткое: Дамерау–Левенштейн ≤ 1 для слов 4–7 символов, ≤ 2 для ≥ 8.

Сортировка: регионы и алиасы выше городов, города по населению. Результатов
не больше 6. `Match{Kind: "region"|"city", RegionCode, City, Name, Fuzzy bool}`.

`func NearestCity(lat, lon float64) (City, float64)` — ближайший город и
расстояние в км; для геолокации город считаем известным, если ближе 30 км.

**Тесты** (табличные): `казань`, `Казнь` (fuzzy → Казань), `питер`,
`г. Москва`, `мо`, `советск` (несколько), `екб`, `югра`,
`Татарстан республика`, `набережные челны`, `ё/е` (`орёл`), пустая строка,
мусор (`asdf` → пусто).

### 3.2. Поведение бота

**Вопрос (R1)** — `bot.region.ask`:

| kid | parent |
|---|---|
| Где ты живёшь? Напиши город или регион — например, «Казань» или «Татарстан». Нужно, чтобы напоминания приходили по твоему времени. | Где живёт {student}? Напишите город или регион — например, «Казань» или «Татарстан». Нужно, чтобы напоминания приходили по местному времени. |

Клавиатура: `[Москва] [Санкт-Петербург]`, `[Московская обл.] [По алфавиту А–Я]`,
`[Не важно]`, `[← Назад]`; после «Назад» первой — выбранное место (раздел 0). Payload: `region:77`, `region:78`, `region:50`, `region:abc`,
`region:skip`. Кнопки геолокации (`request_geo_location`) нет: в MAX она
работает только в мобильном приложении, в веб-версии и на компьютере не
нажимается, а понять, с какого клиента пишет пользователь, бот не может.

**«Не важно»** (`region:skip`): регион не указан — `RegionCode` и `HomeCity`
пустые, ответ `bot.region.skipped`, переход к предметам. Траектория
создаётся с `region_code = ''` и `tz = Europe/Moscow` (`refdata.DefaultTZ`).
Дальше: в «Где учиться» — только Москва и Петербург; в профиле бота «Класс: 9»
без места (`bot.summary.gradeOnly`); ближайшие вузы (V3) считаются от первого
выбранного места; в мини-приложении регион «Не указан», `PATCH /profile`
принимает `region_code: ""`.

| Ключ | kid | parent |
|---|---|---|
| `bot.region.skip` | Не важно | Не важно |
| `bot.region.skipped` | Хорошо. Напоминания будут приходить по московскому времени — поменять можно в профиле. | Хорошо. Напоминания будут приходить по московскому времени — поменять можно в профиле. |

**Ответ текстом** (`freeText` на шаге `region`):

| Результат `Search` | Что делает бот | Экран |
|---|---|---|
| Одно совпадение (не fuzzy) | Сохраняет `RegionCode` (+ `HomeCity`, если это город), шлёт `bot.region.found`, **сразу** переходит к предметам | R2 |
| Несколько | `bot.region.many` + до 6 кнопок `«{Город} · {регион кратко}»`, `[Нет моего — по алфавиту]`. Варианты — в `Draft.PlaceOptions`, payload `region:o:<i>` | R3 |
| Только fuzzy | `bot.region.maybe` + `[Да, {name}]` (`region:o:0`), `[Написать заново]`, `[По алфавиту А–Я]` | R4 |
| Пусто | `bot.region.none` + `[По алфавиту А–Я]` | — |

| Ключ | kid | parent |
|---|---|---|
| `bot.region.found` | {place} → {region} ✓ | {place} → {region} ✓ |
| `bot.region.foundRegion` | {region} ✓ | {region} ✓ |
| `bot.region.change` | Не то, выбрать другой | Не то, выбрать другой |
| `bot.region.many` | Нашёл несколько. Какой твой? | Нашёл несколько. Какой ваш? |
| `bot.region.maybe` | Не нашёл «{query}». Может, это {name} — {region}? | Не нашёл «{query}». Может, это {name} — {region}? |
| `bot.region.maybeYes` | Да, {name} | Да, {name} |
| `bot.region.retry` | Написать заново | Написать заново |
| `bot.region.none` | Не нашёл «{query}». Попробуй написать иначе или выбери по алфавиту. | Не нашёл «{query}». Попробуйте написать иначе или выберите по алфавиту. |
| `bot.region.notMine` | Нет моего — по алфавиту | Нет нашего — по алфавиту |
| `bot.region.alphabet` | По алфавиту А–Я | По алфавиту А–Я |
| `bot.region.letter` | На какую букву твой регион? | На какую букву ваш регион? |
| `bot.region.onLetter` | Регионы на «{letter}»: | Регионы на «{letter}»: |
| `bot.region.otherLetter` | ← Другая буква | ← Другая буква |

Под `bot.region.found` — кнопка `[Не то, выбрать другой]` (`region:change`).
Она работает, пока диалог на шаге `subjects` и предметы ещё не отмечены:
возвращает шаг `region` и заново задаёт вопрос. Позже — `stale`.

**Алфавит (R5).** `region:abc` → буквы, по которым начинаются
`refdata.sortKey` регионов (сейчас 20 букв), по 5 в ряд, payload
`region:l:<буква>`. Буква → регионы на неё по 2 в ряд, подписи кратко
(«Калининградская обл.», «Карачаево-Черкесия»), payload `region:<code>`, и
`[← Другая буква]` (`region:abc`). Под клавиатурой — подсказка «Или напиши
город или регион» (поле ввода). Федеральные округа (`districtList`) из шага
региона убрать.

**Геолокация.** Кнопки нет, но геопозицию, отправленную из вложений в
мобильном MAX, бот понимает: `refdata.Nearest` + `NearestCity` — сохранить
регион (и город, если ближе 30 км), ответить `bot.region.found` /
`foundRegion` с кнопкой `[Не то, выбрать другой]`, перейти к предметам.

## 5. Направления и интересы (экраны A1–A3, P1)

### 5.1. Шаг `direction`

Как сейчас (F8), плюс кнопки внизу:

| Кнопка | Голос | Payload | Куда |
|---|---|---|---|
| `bot.direction.help` — «Не знаю — помоги выбрать» / «Помогите выбрать» | оба | `dir:help` | шаг `interest` |
| `bot.direction.askKid` — «Пусть {student} ответит» | только parent | `dir:kid` | `GoalByKid = true`, направлений нет → шаг `experience` |
| «Решу позже» / «Пока не знаем» (есть) | оба | `dir:later` | без направлений → шаг `experience` (сейчас → `target`) |
| «Готово» (есть) | оба | `dir:done` | шаг `experience` (сейчас → `target`) |

После `dir:kid` бот отвечает `bot.direction.kidLater`:
parent — «Хорошо. Когда закончим, дам ссылку-приглашение: {student} ответит на
пару вопросов про интересы, и подборка обновится у вас обоих.»

### 5.2. Шаг `interest` — В1 (A2)

`bot.interest.ask`:
kid — «Давай разберёмся вместе — два вопроса. Что из этого тебе нравится больше всего? Можно два варианта.»
parent — «Давайте разберёмся — два вопроса. Что из этого больше всего нравится {student_dat}? Можно два варианта.»

Мультивыбор, максимум 2 (третье нажатие → уведомление `bot.interest.max`:
«Можно выбрать два варианта» / то же). «Готово» от одного
(`bot.interest.need`: «Выбери хотя бы один вариант» / «Выберите хотя бы один вариант»).

| Код | Кнопка (оба голоса) |
|---|---|
| `code` | Писать код, делать игры и программы |
| `tasks` | Решать сложные задачи и головоломки |

### 5.4. Подсчёт направлений

Функция `suggestDirections(interests []string, work string, subjects []string, dirs []store.Direction) []string` в `apps/bot` (или `packages/core/pick`), чистая, с тестами.

`score(dir) = Σ interestWeight[код][dir] + workWeight[код][dir] + 1 за каждый любимый предмет в dir.SubjectCodes`.

| `napr-01-03-02` ПМИ | code 1, tasks 2 | research 1, build 1 |
| `napr-09-03-01` ИВТ | code 2, world 1 | build 2 |
| `napr-10-03-01` Информационная безопасность | code 2, tasks 1 | build 1 |

## 7. Где учиться (экраны W1–W3)

Шаг `target`, теперь мультивыбор мест.

`bot.target.ask`: kid — «Где хочешь учиться? Можно выбрать несколько мест или написать город.»
parent — «Где {student} хочет учиться? Можно выбрать несколько мест или написать город.»

Если город ученика не известен (регион выбран по алфавиту или быстрой
кнопкой), к вопросу добавляется `bot.target.cityHint`: kid — «Хочешь именно в
своём городе — напиши его, покажу вузы там.», parent — «Если важно учиться
именно в своём городе — напишите его, покажу вузы там.» (W3)

**Варианты** (`Draft.PlaceOptions`, payload `place:t:<i>`), по порядку:

1. `Только {HomeCity}` — если город известен и это не Москва/Петербург (W1).
2. `Весь регион · {регион кратко}` — свой регион (если не 77/78).
3. `Москва`, `Санкт-Петербург` — если это не свой регион.
4. Места, добавленные текстом, — с «✓» сразу.

Затем `[Другой город]` (`place:other` → подсказка «Напиши город или регион» /
«Напишите…»), `[Не важно]` (`place:any`, снимает остальные отметки и сразу
идёт дальше), `[Готово]` (`place:done`, нужно ≥ 1 места; иначе
`bot.target.need`: «Выбери хотя бы одно место или «Не важно»» / «Выберите…»).

**Текст на этом шаге** → `refdata.Search`: одно совпадение — добавить с «✓» и
ответить `bot.target.added` («Добавил {place}. Что-то ещё?» в обоих голосах),
перерисовав клавиатуру (W2); несколько — кнопки выбора, как на шаге региона.

Выбранное пишется в `Draft.Places` / `PlacesAny`, при создании траектории — в
`trajectory_places`. Кнопку «Другой регион» с федеральными округами убрать.

**Допущение для макетов:** вузы есть во всех регионах. Сейчас в базе 10 вузов
в регионах 77, 50, 78, 54, 16. Пока так, пустой результат на шаге вузов
обрабатывается веткой 8.3 — это нормальный путь, не ошибка.

## 8. Вузы (экраны V1–V3)

### 8.1. Подборка (V1)

`bot.vuz.ask`: kid — «Вот вузы с направлениями {directions} в этих местах. Отметь, куда хочешь поступать, — покажу льготы именно в них. Или напиши название вуза.»
parent — «Вот вузы с направлениями {directions} в этих местах. Отметьте, куда хочет поступать {student}, — покажу льготы именно в них. Или напишите название вуза.»
`{directions}` — названия через запятую со строчной буквы. Без направлений —
`bot.vuz.askAny` без «с направлениями …».

Кнопки `«{short_name} · {city}»`, до 6, по 2 в ряд, payload `vuz:t:<id>`.
Отбор — `SuggestUniversities(directionIDs, places, limit, offset)`: вуз в одном
из мест (город — `universities.city`, регион — `universities.region_code`;
место «весь регион» — только регион), есть хотя бы одно направление;
сортировка как сейчас. Дальше `[Показать ещё]` (`vuz:more`, следующие 6),
`[Пропустить]` / `[Готово]` и `[← Назад]` к шагу `target` (раньше —
`[Изменить места]`, `vuz:places`: со старых сообщений работает). Кнопку
«Другой город» убрать (её заменяет «Назад» к местам).

### 8.2. Поиск по названию (V2)

Текст на шаге `universities` → поиск по `short_name`, `name` и алиасам
(новый словарь `universityAliases` в `apps/bot` или `refdata`): `вышка, вшэ →
hse`; `мгу → msu`; `спбгу, питерский университет → spbu`; `физтех, мфти →
mipt`; `итмо → itmo`; `нгу → nsu`; `кфу, казанский федеральный → kfu`;
`иннополис, уи → innopolis`; `сеченовка, первый мед → sechenov`; `кгму,
казанский медицинский → kazan-gmu`. Найденный вуз добавляется с «✓».

Кампусы (у ВШЭ Москва / СПб / Нижний Новгород / Пермь) — **только если в базе
появятся данные о кампусах** (сейчас у вуза один город). Тогда ответ
`bot.vuz.campus`: «У {uni} несколько кампусов с нужными направлениями. Какой?»
и кнопки `«{uni} · {город}»` + `[Все кампусы]`. Без данных — не делать.

Ничего не найдено — `bot.vuz.notFound`: «Не нашёл вуз «{query}». Попробуй
иначе или выбери из списка.» / «…Попробуйте…».

### 8.3. Нет направления в выбранных местах (V3)

Если подборка пуста, а места и направления выбраны:

`bot.vuz.noDirection`: «В выбранных местах нет программ по направлению «{direction}». Ближайшие вузы, где оно есть:» (оба голоса; если направлений несколько — `bot.vuz.noDirections` «…по выбранным направлениям…»).

Кнопки:

- до 3 × `«+ {short_name} · {city}»` (`vuz:add:<id>`) — вузы с этими
  направлениями, ближайшие к региону ученика по центрам регионов
  (`refdata` lat/lon). Нажатие добавляет вуз и его место в `Places`;
- `[Все вузы с этим направлением]` (`vuz:alldir`) — подборка без фильтра мест;
- `[Похожие здесь: {dir1}, {dir2}]` (`vuz:similar`) — если в выбранных местах
  есть направления с общими ключевыми предметами; добавляет их в `DirectionIDs`;
- `[Пропустить вузы]`.

Оценочных фраз («почти только в МФТИ») не писать: текст собирается из данных.

### 8.4. Пропуск

«Пропустить» оставляем: в подборе включается потенциальная льгота (2.3).

## 9. Итог (экраны B2, B3)

Пользователь ещё ни разу не открывал мини-приложение и не проходил обучение.
Поэтому профиль подтверждается и правится в боте, а итог ведёт в приложение
одной кнопкой.

### 9.1. Карточка профиля — шаг `summary`

После «Готово» / «Пропустить» на шаге вузов (`vuz:done`) диалог переходит на
шаг `summary` (он уже есть в `bot_dialogs_step_check`). Траектории ещё нет:
карточка собирается из черновика. Сообщение с `Format: markdown`:

kid:
```
**{student}, сформировали твой профиль**
Класс: {grade} · {place}
Предметы: {subjects}
Цель: {direction}
Опыт: {experience}
Где учиться: {places}
Вузы: {names}

Всё верно? Если нужно поправить — нажми «Изменить».
```
parent: первая строка `**{me}, сформировали профиль {student_gen}**`, если имя
родителя пустое — `**Сформировали профиль {student_gen}**`; последняя строка
на «вы».

`{place}` — город, если известен, иначе регион. `{direction}` для `suggested`
— с припиской « · подобрали вместе»; без цели — `bot.join.noGoal`, при
`GoalByKid` — «ждёт ответа {student_gen}». `{places}` — «не важно», если мест
нет. `{names}` — «не выбраны», если вузов нет.

Кнопки: `[✏️ Изменить]` (`sum:edit`) и `[Готово]` (`sum:ok`).

### 9.2. «Изменить»

- `sum:edit` правит карточку на месте: вместо «Всё верно?…» — «Что поменять?»,
  кнопки по две в ряд: Имя, Класс, Регион, Предметы, Направления, Опыт, Где
  учиться, Вузы (`sum:f:<поле>`), затем `[← Назад]` (`sum:back`, возвращает
  обычные кнопки). Открытое меню — `Draft.EditMenu`.
- Поле — вопрос того же шага, что в онбординге, без счётчика; у класса без
  «Приятно познакомиться» (`bot.grade.askAgain`). `Draft.EditStage` — номер
  правленого шага.
- Как только шаг уходит дальше правленого, диалог возвращается на `summary` и
  присылает новую карточку. «Помоги выбрать» — тот же шаг 6, «Изменить места»
  со старого сообщения шага вузов — шаг назад: правка продолжается.
- «← Назад» при правке — к меню «Что поменять?» (раздел 0); места при правке
  вузов меняются полем «Где учиться».
- Регион при правке: «Москва ✓» без кнопки «Не то».
- Роль не правится: она меняет голос всех текстов.

### 9.3. «Готово» — итог

`sum:ok` создаёт траекторию (`createTrajectory`, как раньше на шаге вузов) и
присылает одно сообщение. Первая строка — число олимпиад подбора
(`pick.Recommend`, фильтр `all`): `bot.result.one` / `many` — «Под твою цель
подходят 5 олимпиад и ВсОШ.», без цели — `oneSubjects` / `manySubjects` «По
твоим предметам подходят…». Ничего не нашлось — `bot.result.empty`.

Затем стартовая олимпиада из `pick.Start` (2.6):
`bot.result.start`: kid — «Для старта советую эту:», parent — «Для старта советую {student_dat} эту:»; следом отдельными строками
`{olympiad} · {subject}` и `{level} уровень · до {date}, {days} · онлайн`
(«онлайн» — если отбор онлайн).

Следом тем же видом — ближайшая по сроку олимпиада подбора (самый ранний
срок, до которого ещё есть хотя бы день): `bot.result.nearest` «Ближайшая
олимпиада:» (оба голоса). Если стартовая и есть ближайшая, блок один:
`bot.result.startNearest` — kid «Для старта советую эту — она же ближайшая:»,
parent «Для старта советую {student_dat} эту — она же ближайшая:». Затем
`bot.result.tail` / `tailNoVuz`.

Кнопка одна: `[Открыть «Траекторию»]` — `open_app` с `start_param=home`,
новичку мини-приложение показывает обучение. Напоминаний и приглашения в
итоге нет: о трекере и семье рассказывает обучение.

Исключение — родитель нажал «Пусть ответит {student}» (10): первой идёт
`[👋 Пригласить {student_acc}]`, в тексте — `bot.result.kidInvite`.

Приглашённым (родителю сразу, ребёнку после «Всё верно») — тот же итог,
ребёнку с «Отлично!» в начале.

## 10. Родитель и приглашённый ребёнок (экраны P1–P3)
